# Shared hosting deployment - N0C and cPanel

MMI2 is a FastAPI/ASGI application. PlanetHoster N0C and common CloudLinux cPanel Python hosting use Phusion Passenger, which expects WSGI. The project therefore ships a small `a2wsgi` adapter and two compatible entry points:

- `run.py` - N0C / CloudLinux startup file, entry point `app`;
- `passenger_wsgi.py` - cPanel / Passenger entry point, callable `application`.

Both load the same FastAPI application and the same installer.

> Recommended deployment: use the root of a dedicated domain or subdomain, for example `schedule.example.com/`, instead of mounting MMI2 below `/mmi2`. The current web UI uses root-relative URLs such as `/install` and `/admin`.

## Common preparation

1. Point the domain or subdomain to the hosting project.
2. Use Python 3.11 or newer.
3. Create the Python application in the hosting control panel before the final FTP upload when the panel auto-generates starter files.
4. Upload the repository contents into the configured application root.
5. Activate the virtual environment shown by the hosting panel.
6. Run:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

7. Restart the Python application.
8. Open the site. If there is no existing installation, MMI2 redirects to `/install`.
9. Complete the web installer and restart the Python application once more when requested.

The installer runs Alembic migrations itself, creates the owner account and writes `.env`.

## PlanetHoster N0C / MG Panel

N0C provides a Python application manager under **Languages > Python** and uses Passenger behind it.

### Create the application

1. Open the N0C MG Panel.
2. Go to **Languages > Python**.
3. Click **Create**.
4. Select Python 3.11+ if available.
5. Set **App directory** to the directory that will contain MMI2.
6. Set the application domain/URL to the dedicated domain or subdomain and use the root URI `/` when possible.
7. Set **Boot file / Startup file** to:

```text
run.py
```

8. The entry point must be:

```text
app
```

N0C may create starter `run.py` and `passenger_wsgi.py` files. After creating the application, upload the MMI2 repository into the same App directory so the project versions replace the generated starter files.

### Install dependencies

Edit the Python application in N0C and copy the virtualenv activation command shown by the panel. It normally has a form similar to:

```bash
source /home/USERNAME/virtualenv/APP_ROOT/PYTHON_VERSION/bin/activate
```

Then, from the MMI2 application root:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Restart the application from **Languages > Python**.

### Command-line alternative

N0C also supports CloudLinux Selector. The important MMI2 values are:

```text
startup-file: run.py
entry-point: app
```

A deployment can therefore be configured with a command shaped like:

```bash
cloudlinux-selector create --json --interpreter python \
  --app-root APP_ROOT \
  --domain DOMAIN \
  --app-uri / \
  --version PYTHON_VERSION \
  --startup-file run.py \
  --entry-point app
```

Use values reported as available by the hosting account; do not copy the example placeholders literally.

N0C SSH for World/HybridCloud projects normally uses port `5022` unless the account details specify otherwise.

## cPanel / CloudLinux Passenger

PlanetHoster cPanel Python applications also run through Passenger.

1. Open the Python application tool in cPanel (commonly **Setup Python App** / Python Selector).
2. Create an application using Python 3.11+.
3. Choose the repository directory as **Application root**.
4. Prefer a dedicated domain/subdomain at `/`.
5. Configure the startup/WSGI file as:

```text
passenger_wsgi.py
```

6. Configure the application entry point/callable as:

```text
application
```

7. Activate the virtualenv command displayed by cPanel.
8. Run `pip install -r requirements.txt` in the application root.
9. Restart the application from cPanel.
10. Open the domain and complete `/install`.
11. Restart Passenger once again after the installer requests it.

Do not delete or rewrite CloudLinux Passenger directives automatically generated by cPanel in `.htaccess`.

For temporary debugging only, Passenger development/friendly error pages can be enabled from the hosting configuration. Disable detailed errors again in production.

## FTP-only upload

FTP/FTPS transfers the project files, but it cannot by itself create the Python runtime or install packages. You still need the hosting panel to create the Python application. Package installation normally requires either:

- the Python application's package installer, if the panel provides one; or
- SSH access to activate the generated virtualenv and run `pip install -r requirements.txt`.

Once the Python runtime exists, future source updates can be uploaded through FTP and applied by restarting the application.

## PostgreSQL

The web installer supports PostgreSQL, but the database and database user must already exist. The selected user needs permission to create and alter the MMI2 tables and indexes. Alembic creates the schema; it does not create the PostgreSQL database itself.

## Troubleshooting

### 500 Internal Server Error immediately after deployment

Check in this order:

1. Python version is 3.11+;
2. virtualenv is the one associated with the configured application;
3. `pip install -r requirements.txt` completed successfully;
4. N0C uses `run.py` + `app`, or cPanel uses `passenger_wsgi.py` + `application`;
5. the application root is the directory containing `app/`, `install/`, `run.py` and `requirements.txt`;
6. the hosting process can read the files and write `.env` plus `install/` during first installation;
7. inspect the Passenger/Python application error log.

### Installer says restart required

This is expected after first installation. Restart/reload the Python application from N0C/cPanel. On the next process start, MMI2 loads the new `.env` and removes the restart marker automatically.

### Existing installation unexpectedly opens the installer

Do not manually delete `install/install.lock`. MMI2 also detects an existing migrated database containing admin accounts and can adopt it as an existing installation.
